## RES-01 / P1：已受理输入被后续查询错误误报为拒绝

### 问题描述与触发路径

`post()` 顺序执行两个阶段：

```text
POST /v1/inputs
  → 202，后端已经受理，返回 turn_id
GET /v1/turns/{turn_id}
  → 返回查询错误
将错误包装为 sentMsg
```

`Update(sentMsg)` 没有保留错误所属阶段；对任意 HTTP 4xx 均按“输入被后端拒绝”处理，并删除 `pending`、原输入缓存和本地恢复文件。草稿为空时，还会把原文恢复到输入框。

因此，在 POST 明确 202 之后，GET 因鉴权变化或其他查询问题返回 400/401/403/404 时，也会触发拒绝分支。后续查询失败不能推翻已经确认的受理事实。

用户看到拒绝并再次发送恢复的草稿时，`send()` 生成新的 `request_id`，后端可能将其作为第二笔独立输入处理。**这不是后端同键幂等失效，也不声称已经观测到真实重复业务；风险来自客户端丢失已确认受理状态，诱发新键重提。**后台同步有时能发现仍未结束的原请求，但不能抵消错误提示或保证已结束请求仍在 pending 列表。

### 修改建议

- 分离提交结果与观察结果；明确记录 `request_id`、是否已确认受理及已知 `turn_id`。可通过独立消息类型或明确的阶段字段实现，不强制特定重构方式。
- POST 202 一旦确认，后续 GET 的 4xx/5xx/超时/断线只能表示“已受理，暂时无法读取结果”，不能退回未受理或提交拒绝。
- 保留原请求恢复标识和已知轮次身份，恢复后查询原请求/轮次，不自动重新 POST、不生成替代 ID、不因查询失败自动恢复成待重发草稿。权限错误应显示需要恢复认证，不绕过认证重试。
- 只有**提交阶段按后端契约确定未受理**的拒绝，才适用清理追踪和恢复草稿；不覆盖用户正在编辑的另一份草稿。POST 结果未知时继续按原请求查询，不臆断失败。
- 保留现有最小恢复元数据与实例绑定，不为修复额外落盘私人正文。界面状态不会因为迟到查询消息而从已受理/终态退回未受理。

### 验收标准

| ID | 短时场景 | 必须满足 |
|---|---|---|
| R1-01 | 假服务 POST 202，随后 GET 分别返回 400/401/403/404 | 仍明确显示已受理但查询失败；原 request/已知 turn 身份保留，不删除恢复标识，不恢复为待重发原文、不新增 POST |
| R1-02 | POST 202 后 GET 超时或 5xx，恢复连接并完成查询；覆盖客户端重建 | 查询原 request/turn；终态只显示一次，确认终态后才清理追踪；最终仍只有一次原始提交，无新键重复效果 |
| R1-03 | 对照：提交阶段确定拒绝；另一个对照为 POST 响应丢失 | 确定拒绝仍正确提示并在不覆盖新草稿的前提下恢复原草稿；提交结果未知仍保留原 ID 查询，不自动重发；查询失败不能走确定拒绝分支 |

测试使用有状态假调用器或本地假 HTTP 服务即可。必须断言调用顺序、POST 次数、请求/轮次身份、恢复元数据及界面状态，不能只断言错误字符串。

## RES-02 / P2：面板翻页后被定时刷新覆盖回第一页

### 问题描述与触发路径

用户按 `n` 翻页时，`openPanel(name, true)` 使用当前 `panelCursor` 取下一页，`panelMsg.append=true` 将结果追加。

但定时 `tickMsg` 在面板打开且非 busy 时调用 `openPanel(m.panel, false)`，以空游标重新取第一页。返回后 `Update(panelMsg)` 执行：

```go
m.rows = v.page.Items
m.panelCursor = v.page.NextCursor
m.selected = min(m.selected, max(0, len(m.rows)-1))
```

已加载的后续页被替换，游标回到第一页后的游标，选择位置按新列表长度截断。例如两页共 100 条、正在选第 76 条，刷新返回 50 条第一页后，后半页消失并将选择夹回第一页末尾。任务、计划、事项、通知面板均复用这一逻辑。

**已经弹出的控制确认会捕获目标 ID 与版本，不能据此声称确认中的命令必然发错对象。**本项问题是刷新破坏分页浏览与后续选择的稳定性。既有会话原话历史翻页测试不能代替业务面板“翻页＋自动刷新”组合测试。

### 修改建议

- 将分页导航、可见对象身份、选中对象与状态刷新分开管理。可按稳定 ID 合并已加载范围，或采用保留当前页的明确导航设计；不得无提示用第一页覆盖当前查看范围。
- 选中目标按稳定对象 ID 保持，而不是只保留数组下标；对象真实删除或离开列表时明确提示并安全更新选择，不能悄然把另一个对象当作原目标。
- 协调翻页与自动刷新的在途请求，使用查询范围/游标/请求代次等方式忽略过时响应，避免迟到的第一页刷新覆盖新页或已切换的面板。保持有界读取，不改成每秒全库扫描。
- 已打开的控制确认继续绑定原目标与版本；刷新不重新解释用户的确认，也不自动确认通知。

### 验收标准

| ID | 短时场景 | 必须满足 |
|---|---|---|
| R2-01 | 加载至少两页，选中第二页对象后触发正常自动刷新 | 当前浏览对象仍可见，选择仍指向同一 ID，分页游标符合所采用设计；不丢后续页、不跳回第一页、无重复条目 |
| R2-02 | 第一页自动刷新延迟返回，与翻页/切面板响应交错 | 旧响应不能覆盖新页或另一面板；不会重复追加、倒退游标或替换选中目标；不依赖长时间真实等待 |
| R2-03 | 刷新时对象状态/版本变化，另覆盖打开控制确认及目标消失 | 数据变化可见，确认仍绑定原 ID/版本并由后端校验；目标消失有明确提示、不自动改选后执行；刷新没有副作用请求或隐式 ack |

上述场景应以共用面板逻辑的表驱动测试或等效覆盖验证 tasks/jobs/items/notifications，不要求为每种面板复制整套端到端测试。
