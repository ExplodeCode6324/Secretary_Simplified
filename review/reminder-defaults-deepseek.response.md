# 裁决：reminder 默认迟到策略缺失（reviewer: DeepSeek v4.1 Flash）

裁决基准：仅依据题述已核实事实（ExecutionProtocol.md:30、用户自然语言、live-cli-run1 失败产物、model.Encode 信息通道缺失）与给定文档结论。全程不采信任何模型自述作为用户授权依据。

## 一、定性

同意协调方：本事件是实现遗漏，而非设计语义变更。

1. ExecutionProtocol.md:30 已明文提醒默认 FIRE_ONCE_WITHIN_GRACE、宽限默认 5 分钟；用户自然语言未指定迟到策略，属"协议默认应适用且模型无从得知"的情形。
2. model.Encode 的 roleInstruction 未传达该既有默认，导致 Luna 输出 schema 合法但语义错误的 SKIP + grace_seconds=0；Scheduler 按既有严格算法首扫（due+904ms）置 SKIPPED、无通知。schema 合法说明字段级校验无法承载语义正确性判断。
3. 判断落在"决策输入信息通道"而非 runtime/oracle 的依据：+904ms 处于 5 分钟宽限内，按协议语义本应恰好触发一次通知；runtime 与协议一致，run1 保留、oracle 未重写 → 无需改 runtime、无需改 oracle。
4. 语义边界澄清必写进修正："发一次/once"仅是通知次数语义，不构成迟到策略明示，不得被解释为选择 SKIP 的依据。

## 二、充分性裁定

协调方主方案方向正确，但"仅注入默认"不足以构成充分。最小充分修正为两项，缺一不可：

1. 注入既有提醒默认（必要，修正根因）：在 Decision 系统说明中以通用口径注入协议默认与优先级规则——用户明示 > 协议默认；提醒类默认 FIRE_ONCE_WITHIN_GRACE、宽限 5min=300s；用户未指定时不得默选 SKIP/0。措辞必须通用，不得针对本用例特调、不得泄漏预期答案，否则等同改测试标准。
2. 来源契约 + 拒绝式服务校验（必要，最小形态）：当前 schema 字段必填，无法区分"模型选值"与"Master 明示"，这是可审计性缺口。修正为：任何偏离协议默认的迟到策略，必须附带用户原文锚点（原样子串，须能在用户输入中验证存在）；锚点验证不通过 → 决策无效，硬失败且可见，而非静默改写。"模型自称选择了 X""自填来源枚举"一律不构成授权证据——唯有用户输入原文中包含性验证通过的锚点才算授权。
   - 校验范围刻意收窄：仅"提醒类 + 迟到策略偏离默认 + 锚点缺失"这一个条件；不做数值合理性裁决、不引入任何新阈值、不触碰 runtime grace 严格算法。
3. 程序默认回填：不采纳。允许模型省略、由服务层用默认值回填，会把认知缺口变成不可见的静默行为，与必填字段的可审计意图相悖，且正是本次事件要暴露的问题类型。字段保持必填。
4. 不做模型返回后的静默修改：同意，且否决任何"服务端把 SKIP0 悄悄改成 FIRE_ONCE"式补救——那会同时摧毁归因与证据链。正确的三层是：指令预防 + 校验拦截（拒绝非改写）+ 证据保留。

## 三、条件（条件同意的先决条件）

C1 注入内容为通用协议默认与优先级规则（含第一条 4 的语义边界），不得特调、不得泄漏预期。
C2 实现锚点来源契约与拒绝式服务校验（范围见二.2，最小形态）。
C3 重跑为真实 CLI：相同自然语言、相同 oracle；runtime、oracle、run1 报告均不得改动；run2 无论成败原样入档，回改任何一项即整体否决。
C4 验收标准事前固定、不放宽：无锚点前提下决策应为 FIRE_ONCE_WITHIN_GRACE + 300s；首扫处于宽限内 → 恰好一次文字通知；Item 保持 OPEN。通过以"观察到的实际通知与状态"为准，模型说"会发"不算通过。
C5 禁止为通过而重试至成功；run2 若仍失败，按"二试即报"升级上报，不得调 oracle 或引入阈值救场。

## 四、必要回归（最小集，不扩围）

R1 指令构建单测（确定性）：断言 roleInstruction 含提醒默认值与优先级规则。
R2 校验单测（确定性）：无锚点非默认 → 拒绝；有效锚点（用户原文子串）→ 接受；纯默认值免锚点 → 接受；锚点为编造内容（原文不含）→ 拒绝。
R3 runtime 回归：既有 Scheduler 严格算法测试全部保持通过——用于证明 runtime 未动、无阈值变更。
R4 live CLI 重跑：同 C3/C4 执行与留档。

## 五、明确不做（边界）

1. 不改 runtime grace 严格算法；不改 oracle；不重写 run1。
2. 不做模型返回后的静默修正；不做程序默认回填。
3. 不引入额外阈值；不降低测试标准（真实 CLI、真实调度、真实通知观察）。
4. 显式用户迟到策略的保留机制就是第二条的锚点契约：有锚点即接受（哪怕与默认不同），无锚点即无效——显式策略不会被校验门误伤，模型默认也不会被误认为授权。

## 裁决结果

条件同意。协调方定性（实现遗漏）与主体动作（注入、不静默改、不动 runtime、重跑留档）予以采纳；但方案在追加"锚点来源契约 + 拒绝式服务校验（最小形态）"并满足 C1–C5、通过 R1–R4 之前，不视为充分、不得以"通过 run2"为由关闭本条。若 C2 被判定超范围而暂缓，本条维持"条件未满足"状态，以失败入档上报，不得降标放行。
