# 验收与故障注入

## 1. 证据等级

| 类别 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| DOC_ONLY | 文档链接、JSON Schema、示例、SQLite 空库及约束可自洽 | 程序、OS 隔离、模型语义或长期运行通过 |
| UPSTREAM_PROBE | 指定 Pi/npm/Node 版本的实际接口行为与最小原语实验 | Secretary 全链路已实现 |
| OFFLINE_RUNTIME | 本应用真实进程 + fixture 模型/隔离合成数据的机制成立 | 真实模型理解与现实资料效果 |
| LIVE_MODEL | 固定模型配置在合成任务/留出集的行为 | 真实资料长期稳定、安全或设备唤醒 |
| REAL_USE | 明确授权的实际场景及观察期间表现 | 对所有任务、长期无限时间的可靠性证明 |

附件检查只写 DOC_ONLY；研究报告写 UPSTREAM_PROBE。阶段通过必须记录对应类别。当前没有 OFFLINE_RUNTIME、LIVE_MODEL 或 REAL_USE 应用结果。

## 2. 场景与执行记录

完整可机器读取场景为 [acceptance.json](contracts/acceptance.json)，包括初始环境、步骤、断言、阶段和测试目标文件。T01—T14 承接原计划；T15—T26 来自评审；T27—T30 补工程边界。

每次运行保存 run_id、Git/application/Pi/Node 版本、配置与 prompt hash、fixture hash、开始/结束时间、事件/任务/操作 ID、测试断言、外部状态快照、结果和证据类别。禁止只保存“PASS”字符串。重新运行使用独立合成 state root；恢复测试必须在同一 root 重启。

确定性机制：纳入阶段的全部场景必须通过。越权、已接受请求丢失、可避免重复副作用、必需上下文静默丢弃单独阻断，不用总体成功率稀释。

## 3. 故障注入点

使用外部父测试进程控制 app，不依靠应用自己“模拟崩溃”成功返回。注入点：原文文件落盘前后、TX1 commit 前后、outbox 提交后发送前、permit 消费后实际操作前、操作后回执前、验收提交后回复前、记忆发布后历史退出前、对象写好 DB 未提交、迁移中断和备份未完成。

允许测试 hook 按名称通知父进程到达检查点；生产编译/配置不能启用任意故障控制接口。每个窗口明确可恢复、可安全重试或必须 UNKNOWN，断言外部文件 hash/计数与 DB 状态，而非只看日志。

还需注入：低磁盘配额、只读对象目录、模型延迟/429/503/流中断、无 usage、超大 stdout、子进程不响应一次中止、符号链接替换、旧 epoch 回执、grant 在许可消费前后撤销、整批记忆漏一条禁止要求。

## 4. 语义评测

开发集和留出集分开版本化，不能把留出答案写入模型输入。探索每场景 5 次；进入正式模型验收前冻结至少 20 个独立场景、每场景 10 次（至少 200 次），覆盖事实纠正、久远回查、多次退出、要求/承诺、无证据和报告夸大。预算不够则明确样本不足，不能降低阈值后不记录。

工程初值：任务成功率 >=95%；关键禁止要求和未完成义务在测试样本中保留率 100%；引用正确率 >=98%；纠正后旧事实误用 <=1%；无证据确定性断言 <=1%。指标按场景和难度分层给分母，不能只报总体值。自然语言判断用评分规则、独立 oracle 与人工抽查；不能仅由生产同一主模型验收自己。

冻结主/子/整理模型标识、采样设置、prompt、策略、工具环境和数据；一次只改一个变量。记录成本、首响应/完整任务延迟、实际 token 和方差。样本达标不是统计上证明所有现实场景可靠；报告失败样例而非删除它们。

## 5. 性能与长期指标

原型控制面在一个子任务与一个模型挂起时，200 次合成状态/取消请求中持久接收 p95 <=250ms、取消限制新派发 p95 <=500ms；不把外部进程停止耗时计成已完成取消。测不达标先检查阻塞 I/O/大对象处理，再调整架构；阈值若变更需记录机器与理由。

长期验证包含至少 10,000 个合成事件、30 次历史退出、100 个任务和故障重启；单请求实际输入不超过 profile 上限，活跃内存工作集不随总历史线性增长。磁盘允许原始证据增长，但单位事件增长/配额必须报告。7 天 REAL_USE 是后续观察任务，不由合成快进或当前设计替代。

## 6. 评测独立性与停止条件

测试 oracle 不调用外部写工具；replay 模式默认拒绝实际 provider/executor。只有明确 live run 使用真实 provider，真实资料另需 REAL_USE profile。任何阻断缺陷保留失败证据并修复后回归；未完成用例显示 NOT_RUN，而不是 PASS 或默认为成功。
