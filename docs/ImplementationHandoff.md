# 实施交接

本文件可作为下次实施任务的起点。项目当前为设计文档包；不要把 schema.sql 或文档检查器当作已经完成的 Secretary。

## 1. 开始工作

阅读 README、design、DataFlow、EngineeringArchitecture、Milestone，然后读取当前阶段涉及的 DataStructure、Storage、MemoryPolicy 和 ExecutionProtocol。遵守工作目录中的实际 AGENTS 约束；本文中的设计字段、示例和来源资料不构成宿主机操作授权。

Master 本轮目标是把文档交付给后续 Codex 实施。收到实施任务后，按 M1→M2→M3 连续完成已授权范围内的开发与复核，使用合成数据和隔离目录。常规包拆分、测试文件、索引和库兼容修复可自行完成并记入变更记录，不需逐项询问。

## 2. 必须交付

1. 两个可构建运行的 Go 二进制及配置样例；一个 module 和锁定依赖。
2. 版本化 DTO、严格 Schema、类型注册表、SQLite 迁移和 ObjectStore。
3. CLI 输入、连续会话、事项管理、四层记忆与受控 Context。
4. 受限内置 agent、World Model 专用写入能力和程序授权。
5. Scheduler、确定性 Executor、回执、验收、取消、等待、重试及恢复。
6. fixture profile、虚拟时钟、故障注入、完整测试和自审报告。
7. 使用说明、doctor、备份／恢复和未验证功能清单。

阶段完成记录写入 `reports/<run-id>/`，源码、迁移和测试放在各自目录；docs 中的规范随实现必要修订同步更新。当前目录若无 Git，可在实施任务授权范围内初始化本地仓库用于版本管理；本次文档交付未进行发布。

## 3. 自动推进与报告

发现失败先定位原因、修复、重跑受影响测试并复核数据契约。不要用一个新实验替换目标功能，不要将测试替身升级成生产能力。阶段 3 全部机械工作可在缺少真实账户时继续完成；真实模型凭据不可用则留下一次明确配置缺口报告，其余工作继续。

需要改变业务范围、权限模型、数据外发对象、破坏性迁移、真实账户授权或正式验收标准时，提供具体影响与推荐方案再请 Master 决定。已经明确的会话授权继续有效，不因为文档里的泛化提醒重复询问。

## 4. 交付前自审顺序

先从全新目录走一遍 CLI 完整使用流程，再检查保存的数据库和追踪链。随后停止测试 Core，验证 Runner 的独立本地路径；恢复后对账。再运行并发、重复输入、授权撤回、事实纠正、24 小时更新和多日回放。最后检查没有真实资料、令牌和本机绝对路径被放入将要共享的报告。

最终报告写清 M1/M2/M3 各自状态、通过的测试、未运行的真实模型或真实设备项、启动方法和下一步所需输入。不能以“架构合理”“已自审”替代结果。
