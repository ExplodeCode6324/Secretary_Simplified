# 文档复核记录

日期：2026-09-14；范围：本次设计文档包。程序实现与实际使用尚未开始。

## 1. 已复核的跨模块问题

| 问题 | 本版处理 |
|---|---|
| 日更意识可能掩盖日内任务变化 | 24 小时快照与每次读取的当前投影分离，Context 补入增量 |
| World Model 授权被模型自报字段伪造 | 专用能力、程序许可、scope、版本和事实事务内复核 |
| 同输入跨模型重算重复建任务 | 稳定 intent/operation 键、封闭命令组、事务回执 |
| 周期任务首次完成后停止或预算耗尽 | 每 occurrence 独立 Task；时间触发独立执行根，子任务共享预算 |
| 编辑计划重复触发同一时点 | occurrence 身份不含 job revision，保存旧 occurrence 去重 |
| 系统日更命令永久绑定第 0 槽 | 槽控制器派生稳定 UUID 意图并登记当槽一次性命令 |
| 模型输出引用同组新建事项时没有 ID | operation_key 组内绑定，程序预分配 ID 后原子提交 |
| 未知外部结果被当作失败重试 | RESULT_UNKNOWN、能力声明和对账路径 |
| 等待登记期间事件丢失 | 原子现状检查、cursor、generation 与重启补扫 |
| 事实／任务被旧摘要覆盖 | 权威对象版本、快照水位、证据撤回过滤 |
| 异常源数据没有合法保存形态 | QUARANTINED 保留原文，normalized=null 和 validation_error |
| Schema 占满工作上下文 | 只发送输出类型引用闭包，计入完整请求预算 |
| Core 工作重启后没有持久收件记录 | core_work 按 run_id 去重；事实写入与工作结果同事务 |
| 运行记录字段留给实现临时决定 | 主 DTO 与单一 Schema、SQLite 表相互对应，数量由报告统计 |

## 2. 自动检查

可重跑命令与范围见 [checks/README.md](checks/README.md)，最终机器报告见 [latest-report.json](checks/latest-report.json)。检查覆盖文档内部文件链接、主 DTO 字段一致性、Schema 引用、正反样例、原文哈希和空库 DDL 的唯一键／外键／状态约束，以及基本回滚和备份。

首次检查发现 Python JSON Schema 工具未加载可选 RFC3339 校验器，非法时间样例被错误接受；已补充文档工具依赖和启动时的格式校验自检。首次报告保留在 [initial-report.json](checks/initial-report.json)。当时另一个失败项是本复核文档尚未生成的链接，本次已补齐。

最终检查通过：40 个主 DTO 与字段文档一致、54 个 Schema 定义引用有效、14 个正例接受、8 个反例拒绝、34 张表建表成功、14 项 SQL 约束／回滚／备份检查通过。内部链接及示例原文哈希也已检查；精确计数与附件指纹以最终机器报告为准。

这类错误说明自审必须有可失败的反例；“启用了 Schema”本身不能证明所有格式都在校验。Go 实现需单独验证相同反例，不能直接继承 Python 检查结果。

## 3. 证据限制

本次只编写文档和设计附件，执行文档检查与临时 SQLite 测试；未实现 Go 服务、未运行待选 Go 驱动、未接真实来源、未调用文字模型、未生成声音、未进行长期在线测试。自动检查只覆盖它明确列出的机械规则，不能证明所有架构语义和模型行为正确。

原始 Design2.md 按 SHA-256 校验保持原字节。没有修改其他 Secretary 项目、真实资料、网络暴露或系统常驻设置。后续实施需要按 Milestone 和 Acceptance 产生本项目自身的运行证据。
