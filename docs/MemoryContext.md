# 事实、工作记忆与 Context

## 1. 最小知识对象

`Fact` 保存主语、谓词、值/对象关系、适用 scope、有效时间、认识状态、版本、来源证据及替代关系。实体是稳定 ID + 可变名称/别名；名字相同不自动合并。时间不清楚保留 UNKNOWN，不补猜具体时刻。

`Obligation` 统一保存要求、禁止条件、承诺和待决问题：类型、文本、范围（全局/会话/任务）、来源事件、有效状态、可选 due_at/解决事件。未完成义务始终可从权威表查询。它不是自然语言事实摘要，也不自动授予权限。

`Episode` 是闭合经历及可回查引用。`WorkingMemory` 包含当前主题、任务引用、义务引用、未决问题、短经历、连续处理水位和依赖版本，属于派生数据。`ContextManifest` 标识一次调用实际用了哪些状态和证据。

## 2. 认知修改流程

输入/子报告 → FactProposal → Schema 与来源检查 → 身份/政策/当前版本检查 → 自动接纳或等待决定 → TX8 提交。

默认接纳规则：

| 来源或修改 | 处理 |
| --- | --- |
| Master 明确的普通事实/偏好，scope 明确且无冲突 | 可自动接纳为 USER_ASSERTED，引用原始语句 |
| Master 明确纠正指定旧事实 | 新版本取代旧版，保留纠正链；目标不明确先待决 |
| 外部资料或工具观测 | 提案保留 OBSERVED 与来源时间；只有已批准来源规则覆盖时自动接纳，否则待决 |
| 模型推断/子模型建议 | INFERRED 提案，不直接成为 VERIFIED 事实 |
| 授权、删除政策、提供方外发范围、验收放宽 | 走对应可信控制接口，不能借 FactProposal 修改 |
| 来源冲突 | 保留独立断言和 CONFLICTED 状态；不默认最新一句必然正确 |

来源用 `origin_evidence_ids` 去重，转载/摘要指回根来源；重复被检索不能提高证据独立性。当前查询同时检查有效状态、scope 和 valid_from/valid_to，历史查询显式给 as_of。纠正提交使关联索引/摘要失效；Context 读权威事实覆盖旧摘要，工具/提案提交仍检查当前版本。

## 3. 增量整理

调度触发：闭合用户交互段、任务结果接纳、义务/事实更改；30 秒合并抖动，最多每 60 秒检查积压。实时任务/授权状态不等待整理。

一批只读取连续事件 `(watermark, target_seq]` 中当前可完整处理的前缀及必要原文，限制见 defaults。未闭合工具链暂不作为可退出经历。draft 输出主题、经历、义务/任务/事实引用、每个事件的处理分类（covered / no_memory_needed / pending）、缺失项和源片段引用。no_memory_needed 需有程序白名单类型或可审查理由，不能用模型一句“无关”跳过已知义务。

校验顺序：结构 → 引用存在与访问权限 → 水位连续 → 已知权威义务/任务覆盖 → 事实版本有效 → 本批源语句语义抽查/测试 oracle → CAS 提交。任何必需事件 pending/失败，则水位停在它之前；后续成功 draft 可暂存，不能提前宣布覆盖。

未知的新自然语言要求没有可完美证明的自动抽取器。初版将当前输入和未确认覆盖的要求原文保留在必要 Context 中；能确定匹配的结构化控制要求由程序直接记录。长历史中的自然语言抽取质量通过独立留出集验收；出现低置信/冲突/覆盖不清则保留原文并暂停退出，不要求 Master 对每一条普通摘要确认。第二模型复核只提供额外证据。

失败重试最多 3 次，记录错误类别；坏事件进入可见整理阻塞，原事件不删除。人工/确定性修复可产生显式 resolution 事件，以记录为什么该位置可继续处理。不可把死信队列当作已经处理完毕。

事件白名单与防止记忆自触发循环的规则见 [RuntimeProtocol](RuntimeProtocol.md)。纯维护尾部可确定性发布新的记忆版本与匹配水位，不调用模型、不再追加触发同一循环的记忆事件；未知事件类型不能走该捷径。

## 4. 一致 Context 组装

在一个 SQLite 读快照内读取 `cut_seq`、任务版本、world revision、active obligations、授权提示和可用 WorkingMemory 版本。快照结束后调用模型；发生的后续事件由输入代际/业务版本使旧提案被重验，而不是在模型等待期间持有数据库锁。

组装顺序及优先级：

1. 固定系统规则、工具声明、当前身份与能力提示。
2. 当前用户完整输入与直接指向的目标任务/当前事实，适用的有效要求与撤权/纠正信息。
3. 当前未闭合交互段，保留工具调用和结果的合法配对；不构造假 tool result 伪装成功。
4. 与当前工作相关的工作记忆及尚未覆盖的必要事件。
5. 有预算的历史检索和证据片段，显式标为低信任引用材料。

相关性先按 scope/任务/实体关系确定，不只靠模型猜测检索。全局适用要求必须进入；其它任务至少注入必要状态索引，完整详情按需检索。相同来源内容去重，事实变化只计算一次，不因多层重复叙述增加权威。

预算满足：`serialized_input_tokens + output_reserve + safety_margin <= validated_context_limit`。以实际 provider 序列化后的内容为最后门禁，包括 system、工具定义、包装和潜在图片开销；无已验证计数方法的提供方在 P1 不准进入正式 profile。保守估算只用于预筛；记录估计与 usage 差异。模型出口拒绝必须在真实发送前发生。

可选材料按优先级缩短/减少；必要材料放不下则 `CONTEXT_BLOCKED`，显示超限组成和可恢复选项（减小任务范围、处理整理阻塞、明确调整预算）。不悄悄删除要求、不无限触发压缩，不影响无模型控制面。

## 5. 退出与遗忘

退出只能在闭合交互段边界进行，且满足原始对象存在、权威状态已提交、必要语义覆盖可接受、WorkingMemory 水位覆盖、历史可检索。TX7 之后用单独短事务提交 `history_exit_seq <= watermark <= cut_seq`；退出事务还检查当前存储引用完整性。内存视图仅在该提交后替换。崩溃若只提交记忆未退出则保守保留历史，反过来的顺序禁止。

Pi Agent Core 不引入 coding-agent 默认 compaction/分支摘要。主 Agent 在安全空闲边界以新 messages 重建；只缩短一次请求不够，还需释放旧 runtime 对象、监听器和结果缓冲。子 Agent 也使用受控轮换/历史组装，不启用未经过统一模型网关的辅助摘要。

遗忘降低已完成经历的默认权重：近期/活跃任务/高相关优先，其余按需查原文。不修改原始证据，不使任务和承诺失效。删除资料是独立控制流程，见 [Operations](Operations.md)。

## 6. 检索协议

`memory.search` 支持 task_id、entity_id、from/to、关键词、current/as_of、cursor；最多 20 条，单条摘要 1024 字符，总返回 8192 字符。游标绑定查询 hash、cut_seq 和最后排序键；旧游标或无前进结果终止分页，不无限追加。

`evidence.read` 使用对象 ID 和有界 byte range（文本边界安全），不能把任意宿主路径当作对象 ID。返回内容、分类、hash、是否截断、事实有效状态、源事件和证据引用。无结果与检索错误分开，错误不能变成“事实不存在”。所有检索也继承数据分类，返回旧事实必须明确其已失效。
