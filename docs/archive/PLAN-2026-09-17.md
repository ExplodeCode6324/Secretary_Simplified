## 1. 目标与推进原则

在 Pi 的通用 Agent（能调用工具执行任务的智能体）能力之上，实现一个面向 Master、跨进程重启延续的唯一逻辑主会话。主会话通过受控记忆与任务工具协调工作，实际外部检索和任务操作交给子会话。

第一目标是得到可以回放、量化和定位故障的运行闭环。通过标准用例判断系统是否保留了要求、正确完成任务、使用有效事实，并遵守授权边界。

- 先确定可验收行为，再按需要补充字段与模块。
- 按小阶段交付可运行结果；每阶段携带对应测试，不把测试集中留到开发末尾。
- 固定 Pi 上游版本，优先维护薄集成层；阅读完整源码与逐函数注释可继续进行，但不作为所有开发的前置条件。
- 初版限制接入渠道、并发规模和工具数量，保留按任务授权的通用执行能力，避免退化为只能处理少数预登记业务功能的系统。
- 发现失败时先定位记录、记忆、检索、组装、决策或执行环节；只有持续失败且局部改进无效时，才重新评估核心架构。

## 2. 架构约束与初版范围

### 2.1 主会话、子会话与程序服务

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 唯一主会话 | 与 Master 交互；查询记忆、提出认知修改；创建和跟踪任务；接收并验收结果 | 不直接进行任意命令执行或外部资料检索；不能自行证明获得了授权 |
| 子会话 | 根据任务目标与授权，执行外部信息检索、终端操作、文件处理等工作；返回结果和证据 | 不得修改权威认知、授权记录、主会话扩展代码及相关敏感配置 |
| 程序服务 | 持久化、状态校验、授权检查、事件排序、调度、上下文组装及恢复 | 以明确契约执行；不把模型叙述直接提升为权威状态 |

“所有任务交给子会话”指外部检索和实际操作。对话、记忆维护、任务协调属于主会话职责；持久化和预算检查等基础机制由程序直接承担。

主会话身份独立于某次进程、某个 Pi 会话对象和某段历史。用户输入、子任务回执及唤醒事件可以异步到达，但主状态更新必须有序提交。子任务执行期间，主会话仍能接收 Master 的新输入。

能力、工具和任务分别定义：Capability（能力：文件读取、命令执行等可授权操作类别）；Tool（工具：模型可调用的具体接口）；Task（任务：带目标、范围、状态与验收条件的工作实例）。任务授权决定工具实际可操作的资源范围。

### 2.2 初版建议范围

- 一个逻辑主会话，一个文本入口，同一时刻最多运行一个子任务。
- 先支持一个真实只读任务，再增加测试目录内的受控写入或命令执行任务。
- 事件来源先覆盖 Master 输入、主会话输出、子任务交互及状态变化。
- 同一数据库内组织逻辑数据对象；是否需要拆库或拆进程，由实际需求决定。
- 先用任务、实体、时间和关键词查询完成历史回查，再评估语义检索的必要性。
- 定时与条件唤醒、多子任务并发、多客户端、语音、视觉和安卓接入放到基础闭环通过之后。

初版的简化不能省略请求持久化、结果证据、权限检查和基本重启恢复。

## 3. 最小数据契约

先明确以下对象的读写责任与关联方式，再定具体数据库表和字段类型。字段示例用于发现遗漏，实施时以版本化的数据定义为准。

### 3.1 数据对象与候选字段

| 对象 | 用途 | 初版需要表达的信息 |
| --- | --- | --- |
| 原始会话记录 | 保存原始输入、输出、工具请求与回执 | 记录编号、逻辑主会话编号、执行会话编号、角色与来源、时间、正文或内容引用、任务及工具调用关联 |
| 事件日志 | 保存接收、派发、回执、状态提交等过程，支持回放与核查 | 事件编号、持久化顺序、发生时间与接收时间、事件类型、来源、任务关联、因果关联、载荷或引用、去重依据 |
| World Model（世界模型：已接受的事实与关系） | 提供当前有效的事实、实体及关系 | 对象编号、事实或关系内容、适用范围、有效状态、版本、生效与失效信息、来源证据、替代或纠正关系 |
| 任务记录 | 维护任务的权威状态 | 任务编号、请求来源、目标、输入引用、允许能力与资源、验收条件、状态、执行尝试、时限与调用上限、结果引用、剩余问题 |
| 授权记录 | 维护可执行范围及其依据 | 授权编号、授予来源、关联任务或主体、能力与资源范围、有效期或撤销状态、版本 |
| Consciousness State（当前工作记忆） | 派生当前关注点、对话连续性与工作进度 | 版本、已处理事件位置、当前主题、关键约束、任务和待办引用、未决问题、相关经历、证据引用 |
| Context（本次模型输入）组装记录 | 说明某次调用实际使用了什么 | 调用编号、所用状态版本、工作记忆版本、近期事件范围、检索引用、各部分预算与实际输入；按调试需要保存快照 |

原始会话和事件日志可以是同一事实流的不同视图，也可以通过引用关联；不要求重复保存所有大段正文。任务与授权有独立有效状态，不能仅依赖世界模型中的自由文本或工作记忆摘要。

Consciousness State 是可追溯、可重建的派生视图；重建要求语义与关键状态符合契约，不要求模型生成完全相同的措辞。Context 是每轮组装产物，不是新的权威事实源。

### 3.2 必须先明确的更新规则

- [ ] 区分用户陈述、外部观测、工具回执、子会话报告、模型推断与已接受事实。
- [ ] 为原始记录、任务、执行尝试和工具调用建立稳定编号及引用关系。
- [ ] 定义单一逻辑事件流的持久化顺序；发生时间不单独承担排序和去重责任。
- [ ] 去重按稳定请求编号、执行尝试编号及回执编号分别处理；Master 主动再次提出相同内容，可以是新任务，不能按文本相似度直接合并。
- [ ] 定义认知修改的提案、校验、接纳和提交过程，以及哪些修改需要 Master 确认。
- [ ] 定义事实纠正、失效、冲突和未知状态的表达；查询当前事实时排除已失效版本。
- [ ] 定义任务状态更新与对应事件记录的一致性规则。
- [ ] 为派生状态记录版本与处理覆盖范围；重复处理事件不能重复增加事实或推进任务。
- [ ] 处理覆盖位置不能越过尚未完成必要整理的记录；部分失败与重试必须保留可恢复进度。
- [ ] 定义结构版本和迁移方式，使后续字段调整保留原始证据和关联关系。

工作记忆中的关注点变化可以自动派生；权威事实与授权的修改通过受控接口完成。子会话可返回记忆建议，但不得直接提交为正式认知。

## 4. 任务生命周期、授权与恢复

### 4.1 任务交接协议

派发前明确目标、输入、资源范围、授权依据和验收条件。返回结果至少包含：做了什么、实际观察或产物、证据入口、未完成部分、错误与不确定性。

| 状态 | 含义与处理原则 |
| --- | --- |
| 待执行 | 请求已可靠保存；满足授权与派发条件后启动执行 |
| 执行中 | 某次执行尝试已经启动，回执尚未完成接纳 |
| 等待验收 | 已收到结果报告，等待确定性检查及必要的主会话判断 |
| 成功 | 验收条件满足，正式状态与证据已提交 |
| 失败 | 已有明确失败依据，记录原因和可选后续动作 |
| 取消请求中 | 已收到取消意图，后续动作受限，但运行中的外部动作尚未确认停止 |
| 已取消 | 已确认不再继续执行，并记录已有产物或副作用 |
| 结果不确定 | 可能已经发生外部操作，但证据不足，需核查后再决定补交结果或重试 |

授权不足、等待 Master 决定或等待外部条件，应可表达为暂停原因；具体采用附加状态还是状态字段，在数据定义阶段确定。失败或不确定任务若重试，创建新的执行尝试并保留原有记录。

每个执行尝试配置运行时限、调用次数和无进展限制。触及限制后停止派发新的动作，保存已完成结果、在途操作和停止原因；如外部动作无法立即停止，继续按取消与结果核查规则处理，避免无上限循环或递归委派。

子会话报告完成后先进入验收。可以通过文件、返回码或目标状态检查的条件由程序判断；需要语义判断的内容再交主会话。验收并不保证现实结果绝对正确，因此必须保存判断依据与未验证部分。

### 4.2 权限与幂等

Idempotency（幂等性：重复处理同一请求不会重复产生预期外的状态变化）用于请求接纳、回执处理和内部状态提交。涉及外部副作用时，根据目标系统是否支持幂等标识及结果查询选择策略，不宣称所有外部操作都能保证只执行一次。

- [ ] 已接受请求可靠保存之后，才向 Master 确认接收并进入派发。
- [ ] 任务授权与实际资源访问相绑定；在实际操作边界检查有效权限，授权撤销不等待记忆摘要更新。
- [ ] 工具注册、参数校验及文件或进程访问控制共同落实隔离；不能只依赖提示词或隐藏工具名称。
- [ ] 重复回执不会重复验收、重复记账或触发第二次动作。
- [ ] 迟到的回执按任务及执行尝试识别，不覆盖较新结果或取消决定。
- [ ] 收到取消请求后限制后续动作；对已经进行的外部操作核查结果，不把“请求取消”直接等同于“未产生副作用”。
- [ ] 敏感数据处理规则覆盖主会话、子会话、记忆整理及其他辅助模型调用。

### 4.3 最小恢复流程

1. 恢复逻辑主会话身份，读取有效任务、授权、事实和工作记忆版本。
2. 根据派发及结果接纳记录，辨认待执行、执行中、待验收和结果不确定的任务。
3. 对需要核查的外部动作查询实际状态；未确认前不自动重复有副作用的操作。
4. 从工作记忆已处理位置继续整理新增事件，并向当前输入补入必要的未覆盖信息。
5. 恢复主会话交互，将仍在等待或需要 Master 决定的事项明确呈现。

## 5. 增量记忆、上下文退出与渐进式遗忘

### 5.1 更新流程

1. 原始事件及时持久化；任务、授权及已接受事实变化由对应程序接口提交。
2. 从新增原始事件和正式状态变化增量构建工作记忆。
3. 确定性的任务和授权变化及时生效；自然语言经历在适当的完整片段结束后提炼。
4. 保留要求、决策及理由、实际结果、未决问题和证据入口，降低常驻执行细节的比例。
5. 提交工作记忆版本及事件处理位置，保证二者在恢复时相互匹配。已处理位置只推进到连续完成必要处理的事件边界，较新事件成功不能掩盖较早事件的失败或待处理状态。

不以已经混入旧摘要、检索结果和临时资料的完整 Context 反复总结回写。检索得到的旧材料是本次参考，不因再次进入输入就自动成为新发生的经历或新的事实证据。

### 5.2 每轮 Context 组装契约

固定以下输入类别、必要性与预算规则，具体排序和容量通过测试调整：

1. 当前有效约束、任务级权限提示及必要权威状态。
2. 与本轮有关的 Consciousness State。
3. 工作记忆尚未覆盖但本轮必需的新事件。
4. 当前完整交互段，包括仍需继续的工具调用及对应结果。
5. 预算内的检索材料和证据片段。

权限提示只帮助模型理解边界，实际授权仍由执行接口检查。必要待办、授权撤销和事实纠正不能完全依赖模型主动猜测并检索。

Token（模型处理文本的计量单位）预算覆盖输入、工具声明、工具返回、检索材料、输出预留和安全余量。目标是有界且通常接近稳定规模，不要求每轮严格等长。

### 5.3 历史退出条件与故障处理

- [ ] 历史片段已经结束，不破坏当前工具调用与结果的对应关系。
- [ ] 原始内容已经可靠保存，必要状态与经历已被相应记录覆盖。
- [ ] 工作记忆版本、处理覆盖范围和退出位置有一致的提交及恢复规则。
- [ ] 退出后可以通过任务、实体、时间或证据入口找回历史。
- [ ] 记忆整理滞后时补入必要未覆盖信息；记录尚未满足退出条件时不得为了缩短输入而直接丢弃。
- [ ] 遇到过大工具结果，保存完整内容并返回有界片段或引用；必要信息仍放不下时暂停下一次模型调用并进入明确恢复流程。
- [ ] 同时管理 Pi 的运行时历史和存储增长；缩短模型请求不等于内存对象或磁盘记录已经缩小。

达到预算触发历史退出，记忆更新在此前持续发生。正常退出流程不依赖对完整 Context 做反复摘要。

### 5.4 渐进式遗忘与检索

遗忘指降低默认注入优先级或退出常驻工作集，不删除原始证据，也不把事实不断改写得更模糊。

- 未完成任务、承诺、待审批事项由持久状态保障；未来唤醒由调度记录保障。
- 已纠正或失效的事实保留版本关系，历史查询可见，当前事实查询不继续采用。
- 已结束经历可以降低常驻优先级，需要时通过索引检索。
- 检索返回内容、有效状态、来源和证据入口，并有明确的结果数量及长度预算。
- 检索失败或证据冲突时说明缺失或不确定，不凭模型印象补全。
- 每日归档、快照和复杂遗忘评分属于可选优化，不作为连续性成立的必要前提。

### 5.5 与 Pi 历史管理的关系

实施时检查 Pi 的自动压缩、手动压缩、分支摘要、会话恢复和溢出处理入口。主会话应明确由谁维护记忆、由谁控制预算，避免两个独立摘要流程同时回写。

是否关闭、替换或保留默认压缩兜底，由集成和故障验证确定。子会话可以先保留 Pi 的常规局部历史管理。上游版本升级后重新运行相关回归测试。

## 6. 分阶段实施顺序

### P0：确定范围与验收用例

目标：在详细字段和代码之前，明确什么叫“运行正确”。

- [ ] 核对第 2 节架构边界，区分既定原则与暂定参数。
- [ ] 确定初版渠道、工具、模型配置、运行环境和数据保存范围。
- [ ] 编写第 7 节场景的输入、预期外部状态、允许误差和失败判定。
- [ ] 留出不参与调参的验收场景。

交付物：初版范围、场景清单、验收规则。  
通过条件：能依据行为与外部状态判断成败，不依赖固定摘要措辞。

### P1：Pi 源码解读与集成验证

目标：用少量实验确认接入路径，再决定是否需要修改上游代码。

- [ ] 固定运行所用 Pi 提交版本，记录依赖与启动方式。
- [ ] 阅读输入接收、Agent 循环、工具调用、事件输出、会话持久化及模型输入转换路径。
- [ ] 建立独立主会话和子会话，验证各自的工具与扩展加载范围。
- [ ] 验证调整本轮模型输入的入口及工具调用、结果的合法对应关系。
- [ ] 检查默认压缩及其他历史整理路径，验证恢复时的行为。
- [ ] 记录集成决策和仍需验证的问题；教学源码版本与运行版本分别管理。

交付物：可运行集成实验、上游版本记录、必要调用链说明。  
通过条件：实际运行证明可以隔离会话、接收事件和控制模型输入；仅阅读文档不算完成。

### P2：最小数据模型与程序契约

目标：让生命周期、持久化和恢复规则可以独立于真实模型验证。

- [ ] 定义原始记录、事件、任务、授权及逻辑主会话标识。
- [ ] 实现状态变化校验、原始记录保存和正式状态提交。
- [ ] 实现输入、派发、回执的稳定关联与去重。
- [ ] 用模拟子会话验证正常、失败、重复、取消和崩溃恢复路径。
- [ ] 预留认知及工作记忆的版本和证据引用约定，避免提前填满全部领域字段。

交付物：最小存储定义、任务契约、确定性机制测试。  
通过条件：已接受请求可恢复，重复回执不重复提交状态，失败路径可解释。

### P3：真实主子会话闭环与基础恢复

目标：在复杂记忆策略介入前，先可靠地完成一次任务。

- [ ] 主会话保存并派发任务，子会话执行并返回结构化结果与证据。
- [ ] 实现结果验收、状态提交、向 Master 回复。
- [ ] 验证子任务运行期间主会话仍能响应输入、查询和取消请求。
- [ ] 实现运行时限、调用次数和无进展退出，返回已有结果与停止原因。
- [ ] 落实最小资源隔离，测试子会话无法修改受保护状态。
- [ ] 完成正常重启及关键中断位置的恢复验证。
- [ ] 在测试目录加入一个受控写入或命令任务，验证通用能力与授权绑定，并检查重复副作用风险。

交付物：文本入口、主子会话协调、受限通用工具、任务证据与恢复能力。  
通过条件：只读任务完整运行；受控操作符合授权；重启后能说明做了什么、依据是什么、还有什么未完成。

### P4：事实记忆与基础检索

目标：先建立可靠保存、纠正与回查的能力，为历史退出做准备。

- [ ] 实现最小世界模型、事实来源、版本与有效状态。
- [ ] 实现受控认知修改提案、校验及接纳接口。
- [ ] 实现任务、实体、时间和关键词查询，以及原始证据回查。
- [ ] 验证事实纠正、来源冲突、无证据和检索失败处理。
- [ ] 验证子会话的记忆建议只能通过接纳流程进入正式状态。

交付物：事实维护接口、历史查询工具、版本与证据链。  
通过条件：能记住、纠正、找回和说明依据；旧事实不会继续被当作当前事实返回。

### P5：增量工作记忆与稳定上下文组装

目标：以新增事件保持连续性，建立可测量的模型输入契约。

- [ ] 实现增量记忆整理与工作记忆结构校验。
- [ ] 保存工作记忆版本及对应事件处理位置。
- [ ] 实现必要状态、相关工作记忆、未覆盖新事件和当前交互段的组装。
- [ ] 验证整理失败、重复处理、滞后及重启时的恢复和补入规则。
- [ ] 保存调试所需的实际请求快照、输入组成与模型配置。

交付物：增量记忆处理、上下文组装、输入追踪。  
通过条件：新增要求不会因整理滞后而遗漏；当前约束、任务与事实变化能进入正确调用；旧检索材料不会反复回流成为新事实。

### P6：退出、渐进式遗忘与预算控制

目标：在多次历史退出后保持任务与对话连续性。

- [ ] 实现符合第 5 节条件的历史退出及一致性提交。
- [ ] 实现工作集优先级下降和按需恢复。
- [ ] 纳入工具声明、返回、检索与输出预留，记录各部分预算。
- [ ] 验证超大返回、无法满足预算、整理失败及退出过程崩溃。
- [ ] 验证 Pi 默认历史管理与 Secretary 策略不会形成双重摘要回写。
- [ ] 测量长期运行时请求规模、内存占用、存储增长、延迟和辅助模型成本。

交付物：有界上下文、可追溯退出与检索、预算及故障处理。  
通过条件：多次退出后任务约束和待办仍然有效，历史证据可找回，超预算路径不会静默丢弃必要信息。

### P7：扩展接入与持续优化

目标：基础闭环通过后，再增加运行规模与输入渠道。

- [ ] 加入持久定时和条件唤醒，验证重启后仍能触发且不重复执行。
- [ ] 支持多个子任务，处理乱序、迟到结果和资源冲突。
- [ ] 支持多客户端，并保持唯一逻辑主会话与主状态有序提交。
- [ ] 按实际需求接入语音、视觉、安卓或其他数据源。
- [ ] 通过对照实验决定是否加入语义检索、复杂遗忘评分或独立服务。
- [ ] 每次上游升级和真实故障修复都运行回归用例。

交付物：经验证的扩展能力和持续回归记录。  
通过条件：新增功能通过专用用例，且已有关键行为没有退化。

## 7. 测试计划与验收标准

### 7.1 初始场景矩阵

| 编号 | 场景 | 核心检查 | 首次纳入阶段 |
| --- | --- | --- | --- |
| T01 | Master 请求读取测试文件或检索外部资料 | 主会话正确派发；子会话返回来源；结果经验收后回复 | P1、P3 |
| T02 | 同一稳定请求编号或回执编号重复投递 | 不重复创建执行或提交已处理结果；Master 再次主动提出相同内容时仍可建立新任务 | P2 |
| T03 | 在接收、派发、执行、结果接纳之间中断并重启 | 已接受请求不丢失；恢复能区分未执行、已完成和结果不确定 | P2、P3 |
| T04 | 执行中继续对话、取消或撤销授权 | 主会话可响应；后续操作受限；迟到回执和已有副作用得到正确处理 | P2、P3 |
| T05 | 子会话尝试修改权威认知、授权或主会话配置 | 工具及实际资源访问均无法越权；日志或工具内容不能自授权限 | P3、P4 |
| T06 | Master 纠正事实，或来源彼此冲突 | 当前回答使用有效状态；旧版本可追溯；不确定部分被保留 | P4 |
| T07 | 久远资料退出工作集后被询问，或确实查不到 | 能按线索找回原文；没有证据时明确缺失 | P4、P6 |
| T08 | 记忆整理延迟、失败或重复运行 | 必要未覆盖事件补入；事件位置与记忆版本匹配；重试不污染状态 | P5 |
| T09 | 同一旧摘要或检索结果多次进入模型输入 | 不被反复认作新证据，不凭重复出现提高事实权威性 | P5 |
| T10 | 长任务跨多次退出，期间加入新约束或留下承诺 | 目标、约束、进度、待办及证据仍有效；未完成事项不因时间遗忘 | P5、P6 |
| T11 | 工具结果过大、输入预算不足或当前工具链未结束 | 预算控制有明确结果；不破坏调用与回执配对；不静默丢失必要信息 | P1、P6 |
| T12 | 长时运行、定时唤醒、多任务或多客户端同时到达 | 分阶段检查请求规模、成本、恢复、触发去重及主状态有序提交 | P6、P7 |
| T13 | 子会话自报成功但证据缺失、产物不符或仅格式正确 | 不直接提交为成功；按验收规则检查目标状态，保留未验证和失败部分 | P3 |
| T14 | 重复失败、无进展或超过运行时间与调用次数 | 停止新增动作并记录原因；已有产物可回查，在途副作用继续核查 | P2、P3 |

每个场景记录初始数据、输入事件、预期状态、证据要求、检查方式、实际输出和失败原因。覆盖至少一次成功路径和对应失败或边界路径。

### 7.2 两类验收分开处理

**程序机制：**对持久化、状态变化、去重、授权、版本和预算使用确定性断言。纳入当前阶段的必需机制用例应全部通过。越权、丢失已接受请求、可防止却发生的重复副作用，作为独立阻断项，不能被总体成功率抵消。

**模型行为：**对任务理解、记忆提炼、事实使用、检索选择及语义验收进行多次真实运行。检查行为和外部结果，不要求固定措辞或唯一工具调用路径。能用程序判定的部分优先自动检查，自然语言质量以明确评分规则和人工抽查补充。

建议初次探索每个模型行为场景运行 5 次，用于尽早暴露波动；正式样本量、成功率阈值和允许延迟由 P0/P1 的成本及初测结果决定，并在后续调参前记录。少量用例通过不等于证明系统在所有情况下可靠。

### 7.3 指标与对照实验

- 任务验收成功率，以及失败类型分布。
- 关键约束与未完成事项保留率。
- 事实纠正后仍采用旧事实的比例，以及无证据断言的比例。
- 历史证据检索命中率和引用正确性。
- 恢复成功率、重复状态提交次数及重复副作用事件。
- 输入规模、预算异常、调用次数、首个响应及完整任务延迟。
- 主模型、子会话、记忆整理等各条调用路径的成本，以及运行内存和存储增长。

对照实验尽量固定模型版本、配置、任务数据和工具环境，一次改变一个记忆或组装策略。保留未参与调参的验收集；上线后的真实失败转成回归用例。

### 7.4 故障定位顺序

按照以下顺序核查：原始信息是否保存 → 权威状态和工作记忆是否更新 → 是否检索到 → 是否进入实际模型输入 → 模型是否正确决定 → 工具是否正确执行 → 结果是否正确验收与提交。

每次失败保留能支持上述核查的事件编号、版本、调用输入、工具结果和外部证据；记录保存及辅助模型调用遵守相同的数据访问规则。

## 8. 第一项可运行成果

选择测试目录内一个内容已知的文件，由 Master 请求读取并回答其中一个问题。

以下过程中，原始事件随发生及时持久化；先保存请求、结果和证据，再提交相应正式状态与发送确认。

1. 主会话保存请求，生成包含范围和验收条件的任务。
2. 子会话在授权范围内读取文件，返回答案、来源与必要证据；接收方可靠保存结果。
3. 程序及主会话验收结果，提交任务状态、验收依据及回复记录，再向 Master 回复。
4. 核查原始交互、执行记录、结果依据及其引用是否完整。
5. 重启进程，再询问这项任务做了什么、依据是什么、是否仍有未完成部分。

这一闭环首先依靠持久任务和原始记录恢复，不要求提前完成丰富世界模型、复杂遗忘算法或完整长期记忆。通过后按 P4—P6 加入记忆能力，观察它对连续性、成本和故障率的实际影响。
